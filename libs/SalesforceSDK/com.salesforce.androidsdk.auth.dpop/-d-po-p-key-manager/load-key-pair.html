loadKeyPair

@RestrictTo(value = [RestrictTo.Scope.LIBRARY])
fun loadKeyPair(alias: String): KeyPair?

Load-only lookup: returns the key pair already bound for alias, or null if no key is present. Unlike generateOrLoadKeyPair this NEVER mints a key on a miss — it is the side-effect-free primitive the refresh and request-decoration paths must use so a credential whose bound key has gone missing (device restore, keystore eviction) fails fast and routes to re-auth instead of silently signing with a non-bound key.

A genuine absence (getKey returns null) yields null. A KeyStore access failure (device lock, keystore error) is rethrown so callers can distinguish "key is gone" from "could not read the keystore right now" and avoid turning a transient error into a logout.

Not part of the public SDK surface — RestrictTo keeps it out of the public API (so it is safe to introduce in a patch release) while remaining callable from other SDK modules, including the Java OAuth2 refresh path. (Kotlin internal is not an option here: it is name-mangled in bytecode and cannot be called from the Java callers.)
